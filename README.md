# Генератор синтетических ТЗ с известными дефектами

Нужен для одного: **измерить полноту** инструмента ревью документации.

Точность известна: 83% на слепой внутренней разметке, 58% на внешней
разметке кейсодателя. Полноту кейсодатель назвал главным критерием —
пропущенная ошибка хуже придирки. На выданных документах её измерить
нельзя: они прошли ревью тремя командами, эталонного перечня дефектов
в них нет. Здесь эталон известен по построению.

## Запуск

```bash
python generate.py --out data/synth
```

На каждый документ три файла:

| Файл | Что это |
|---|---|
| `synth_N.txt` | документ с дефектами, плоский текст |
| `synth_N_clean.txt` | тот же документ до мутаций, негативный контроль |
| `synth_N_truth.json` | эталон |

Плюс `synth_manifest.json` — сводка по набору.

## Три класса дефектов

Первый замер показал, что единого правила сопоставления не существует.
Если из документа вырезали строку про объём данных, процитировать её
нельзя. Инструмент указывает на соседнюю строку требований, на путь
HDFS или на заголовок раздела — все три ответа по смыслу верны, а
сопоставление по дословной цитате объявляет промахом два из трёх.

Поэтому дефекты разделены, и каждый класс меряется своим правилом.

**`presence`** — испорченный текст в документе есть: заглушка вместо
значения, вставленное противоречащее утверждение, мера в списке
группировки, обрезанный срок хранения. Сопоставление строгое, по
дословной цитате. Требование точной привязки здесь законно.

**`absence`** — содержание вырезано, контейнер остался. Попаданием
считается указание на любую строку того раздела или шага, где
содержание должно быть. В эталоне лежат `containers` и
`container_lines`, а также `removed_text` — что именно вырезано.

**`section_removed`** — раздел шаблона удалён целиком, контейнера не
осталось. Попаданием считается упоминание имени раздела в цитате или
в объяснении замечания.

В текущем наборе: 40 наличия, 21 отсутствия, 4 удалённых раздела.

## Как измерять

```bash
# весь набор: замечания модели плюс детерминированный слой
python score.py --batch data/synth results

# один документ
python score.py --truth data/synth/synth_1_truth.json \
                --findings results/synth_1_full2.json \
                           results/formal/synth_1_formal.json

# негативный контроль
python score.py --clean results/synth_1_clean_full2.json
```

`--batch` сам подмешивает `results/formal/{doc}_formal.json` к замечаниям
модели. Без этого 14 дефектов класса `deterministic` считаются
пропущенными: модель их не ищет, они отданы `check_formal.py`.

Суффикс файла замечаний модели задаётся `--suffix` (по умолчанию
`_full2`).

Полнота выводится в шести разрезах: все, три класса, два слоя. И в двух
режимах: **по месту** (замечание указало куда надо) и **по месту и
типу** (плюс верно назвало тип).

## Устройство

Принципиальное решение: **не «сгенерировать текст и потом разметить
дефекты»**. При таком порядке эталон становится предметом суждения,
и измерение полноты обесценивается.

Порядок обратный:

1. `domains.py` собирает чистый документ по шаблону кейсодателя.
   Документ — дерево узлов с устойчивыми id, а не строка.
2. `mutators.py` применяет рецепты. Каждый портит документ известным
   способом в известном месте и сам записывает запись эталона.
3. Рендер выполняется **один раз после всех мутаций**.
4. Для `presence` цитата берётся из отрендеренного текста по id якоря.
   Для `absence` контейнер вычисляется до мутации — ближайший шаг или
   раздел, содержавший удалённый узел.

Дословность цитаты обеспечена по построению, а не проверкой постфактум.

### Инварианты, проверяемые при генерации

Генератор завершается с ненулевым кодом, если нарушено хоть что-то:

- `presence` — цитата встречается в документе дословно и ровно один раз;
- `absence` — все строки контейнера присутствуют в документе;
- `section_removed` — имя раздела в документе отсутствует;
- две мутации не бьют в один узел, якоря `presence` не повторяются;
- каждый тип дефекта встречается в наборе не менее двух раз.

## Набор

| Документ | Домен | Дефектов |
|---|---|---|
| synth_1 | интернет-трафик | 16 |
| synth_2 | качество радиосети | 14 |
| synth_3 | отток абонентов | 4 |
| synth_4 | роуминг | 17 |
| synth_5 | подключённые услуги | 14 |

Всего 65 дефектов, 25 типов, из них 5 типов ловятся детерминированной
проверкой без модели.

`synth_3` намеренно почти чистый — проверка, что инструмент не начинает
выдумывать замечания на хорошем тексте. Домены разные, чтобы дефекты
не оказались привязаны к одному сюжету.

В каждом документе два-три раздела помечены «не применимо» — это норма,
а не дефект: правило кейсодателя требует сохранять разделы шаблона
с такой пометкой.

Отдельно в чистых документах присутствуют четыре ситуации, которые
кейсодатель **явно назвал не дефектами** при разметке 3 сентября:
полностью описанное ветвление логики, месячная перезагрузка без правила
дедупликации, историчные справочники без отдельной оговорки, ссылки
на внешние описания. Инструмент не должен на них срабатывать.

## Почему базовый текст пишется кодом, а не моделью

Если генератор и ревьюер — одна модель, полнота окажется завышенной:
модель ищет то, что сама умеет формулировать. Другая модель это
смягчает, но не снимает. Детерминированный контент снимает вопрос
целиком и даёт воспроизводимость: два прогона дают побайтово
одинаковый набор.

Цена — содержание пяти доменов написано руками в `domains.py`,
около 400 строк данных.

## Соглашения об именовании

`TABLE_*`, `FIELD_*`, `SCHEMA_*`, `TOPIC_*`, `USER_*` — обезличивание,
а не заглушки. Настоящие заглушки, которые вносятся как дефект:
`CLUSTER` без имени, `LINK_*` вместо ссылки, `PROJECT-XX` вместо номера
задачи, «Папка» вместо пути. В чистых документах ссылки настоящие
(`https://datacatalog.corp/...`), иначе негативный контроль сам бы
срабатывал на `PLACEHOLDER_LEFT`.

## Ограничения

- Документы содержат только вымышленные объекты. Документы кейсодателя
  в репозиторий не попадают.
- Гиперссылки в плоском тексте не размечены. Пока извлечение docx
  не сохраняет `w:hyperlink`, типы `DATA_CATALOG_MISSING` и
  `DANGLING_REFERENCE` измеряются в суженном виде.
- Сопоставление `absence` по контейнеру мягче, чем по цитате. Это
  осознанный выбор: строгое требование к дефекту отсутствия
  неисполнимо. При разборе результатов это стоит называть прямо.
