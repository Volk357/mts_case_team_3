# Контрольный прогон: что дало рост слоя модели (4 сентября 2026)

## Вопрос

Между прогонами 3 и 4 сентября слой модели вырос с 68% до 84% на том же эталоне.
В материалах это стояло как «не объяснено», а ходовое объяснение звучало так:
«шесть типов переведены в детерминированный слой и убраны из промпта».

## Первое: ходовое объяснение оказалось ложным в посылке

Проверено кодом, а не рассуждением. `render_taxonomy` (`run_review.py`) не фильтрует
типы по `detectable_by`, `load_taxonomy` отдаёт весь список. **В промпт попадают все типы той версии
файла, что подана на вход: 26 в таксономии 3 сентября, 29 в текущей. `detectable_by`
их не фильтрует.** Переведённые типы исчезли только из
ВЫДАЧИ — их отбрасывает межслойный фильтр в `run_full` и `score.gather`. Файл
`defects_prompt.yaml`, который правился в тот день, в измеренных прогонах не участвует:
и `run_review.py`, и `docreview.py` по умолчанию читают `defects.yaml`.

Формулировку «мы сузили промпт» произносить нельзя — она неверна.

## Второе: однофакторный контрольный прогон

Единственное различие между условиями — файл таксономии. Код, JSON-схема вывода,
бюджет, межслойный фильтр, эталон, температура — идентичны.

| Условие | Слой модели | Полнота по месту |
|---|---|---|
| Таксономия 3 сентября (`git show ef400c3:defects.yaml`) | **66%** (25/38) | 78% (51/65) |
| Таксономия 4 сентября (текущая) | **84%** (32/38) | 89% (58/65) |

## Третье: поправка на артефакт измерения

В контрольном условии 5 модельных находок типа `TIMEZONE_UNDEFINED` отбрасываются
сегодняшним межслойным фильтром (в старой таксономии этот тип — модельный, в новой —
детерминированный). Чтобы это не завышало разрыв, контроль пересчитан БЕЗ фильтра,
то есть в его пользу:

| Условие | Слой модели |
|---|---|
| Контроль, как считаем всегда | 25/38 = 66% |
| Контроль без фильтра — верхняя граница | 26/38 = 68% |
| Текущая таксономия | 32/38 = 84% |

Разрыв 6 дефектов при разбросе между прогонами ±1. Артефакт объясняет не более одного.

## Разложение прироста по типам — оно противоречит простому объяснению

Разложение сделано для пары «контроль прогон 1 — текущее условие прогон 3»
(25 → 32 без поправки на фильтр): девять дефектов стали находиться, два перестали.
Ни один из них не относится к шести отредактированным типам:

| Стало находиться | Перестало |
|---|---|
| FILTER_RESULT_UNDEFINED ×2, NO_SCHEDULE ×2, MISSING_SOURCE_LOCATION, AMBIGUOUS_LOGIC, NO_DEDUP_OR_KEY, TEXT_STRUCTURE_ERROR, NO_VOLUME_ESTIMATE | AMBIGUOUS_LOGIC, UNSPECIFIED_FORMAT |

Правки касались `TIMEZONE_*`, `DANGLING_*`, `SCHEMA_*`. Прирост пришёлся на другие типы.
Значит объяснение «уточнили определения — модель точнее ставит эти типы» **не
подтверждается**: эффект не локализован там, где были правки. Остаются варианты:
глобальное влияние структуры и объёма таксономии на поведение модели, либо разброс
между прогонами больше, чем ±1, измеренный на текущем условии.

## Повторные прогоны: эффект воспроизводим

По замечанию ревьюера (одного повторения на условие для причинного вывода мало) прогоны
повторены. Итого шесть: два контрольных и четыре в текущем условии.

| Условие | Слой модели (из 38) | Полнота по месту |
|---|---|---|
| Старая таксономия, прогон 1 | 25 (66%) | 78% |
| Старая таксономия, прогон 2 | 26 (68%) | 80% |
| Текущая, прогон 1 | 32 (84%) | 89% |
| Текущая, прогон 2 | 31 (82%) | 88% |
| Текущая, прогон 3 | 32 (84%) | 89% |
| Текущая, прогон 4 | 31 (82%) | 88% |

**Диапазоны не пересекаются:** 25–26 против 31–32. Разрыв 5–7 дефектов до поправки
на артефакт межслойного фильтра и 5–6 после неё, при внутреннем разбросе в каждом
условии ±1. Внутри каждого условия результат устойчив.

## Что можно утверждать, а что нет

**Можно:** замена файла таксономии воспроизводимо меняет полноту слоя модели
с 25–26 до 31–32 дефектов из 38 (два прогона против четырёх, диапазоны не пересекаются).
Известный артефакт межслойного фильтра меняет оценку контроля на один дефект.

**Нельзя утверждать механизм.** Разложение прироста по типам показывает, что
дополнительные попадания пришлись на типы, которых правки НЕ касались
(FILTER_RESULT_UNDEFINED, NO_SCHEDULE, MISSING_SOURCE_LOCATION и др.), а не на
отредактированные `TIMEZONE_*`, `DANGLING_*`, `SCHEMA_*`. Поэтому объяснение
«уточнили определения — модель точнее ставит именно эти типы» не подтверждается.
Остаётся глобальный эффект: другой объём и структура списка типов меняют поведение
модели на всём документе. Это гипотеза, отдельно не проверенная.

**Нельзя сказать «дело в тексте промпта».** Эксперимент изолирует файл ЦЕЛИКОМ:
текст для промпта, множество допустимых идентификаторов (`verify` отбрасывает
неизвестные — в обоих условиях таких отбрасываний 0) и разметку `detectable_by`,
управляющую межслойным фильтром.

## Воспроизведение

```bash
# одно повторение контрольного условия
OLD=results/old_run1
for i in 1 2 3 4 5; do
  python3 check_formal.py --doc data/synth/synth_$i.txt --out $OLD/formal
  python3 run_review.py  --doc data/synth/synth_$i.txt --mode full2 \
      --defects data/ab_taxonomy/defects_03sep.yaml --out $OLD
done
python3 score.py --batch data/synth $OLD

# одно повторение текущего условия — ОБЯЗАТЕЛЬНО другой каталог
NEW=results/new_run1
for i in 1 2 3 4 5; do
  python3 check_formal.py --doc data/synth/synth_$i.txt --out $NEW/formal
  python3 run_review.py  --doc data/synth/synth_$i.txt --mode full2 --out $NEW
done
python3 score.py --batch data/synth $NEW
```

Каждое повторение пишется в СВОЙ каталог: `score.py` ищет формальный слой внутри
каталога оцениваемого прогона (`<каталог>/formal/`), а общий каталог привёл бы
к перезаписи выдач одного условия другим. Выполнено шесть повторений:
два контрольных и четыре текущих.

Модель `qwen3:30b-a3b` (Q4_K_M), `NUM_CTX=32768`, temperature 0, эндпоинт из `OLLAMA_URL`.
Код на момент прогонов — коммит `ebb7e30`. Сырые выдачи всех шести повторений лежат
в `outputs/` (по пять документов в каждой серии): `*_oldtax_full2.json`
и `*_oldtax_run2_full2.json` — два контрольных прогона; `*_newtax_full2.json`,
`*_newtax_run2_full2.json`, `*_newtax_run3_full2.json`, `*_newtax_run4_full2.json` —
четыре прогона текущего условия. Там же
`outputs/formal/` — выдачи формального слоя, общие для обоих условий. Файл старой
таксономии — `defects_03sep.yaml`.

(Каталог назван `outputs`, а не `runs`: `runs/` попадает под правило `.gitignore`
и файлы не попали бы в репозиторий.)
