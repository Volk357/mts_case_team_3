# Локальная модель

Analysis Core обращается к локальной языковой модели через Ollama. Наружных
API-провайдеров в контуре нет: все замеры качества сняты на этой сборке.

## Точная сборка модели (нужна для воспроизводимости)

Результаты слоя модели воспроизводятся только на той же сборке. Смена версии,
кванта или даже пересборка тега `qwen3:30b-a3b` даст другие числа, и заявленную
полноту тогда придётся переснимать. Значения ниже сняты с работающего сервера
(`GET /api/tags`), а не переписаны из заметок.

| Параметр | Значение |
|---|---|
| Тег | `qwen3:30b-a3b` |
| Квантование | `Q4_K_M` |
| Размер параметров | 30.5B, семейство `qwen3moe` |
| Размер на диске | 17.3 ГиБ |
| SHA-256 сборки | `ad815644918f0eaab341c12b67837cc6dd4562342cdaf118f83d5d554cb37226` |
| Загружена | 3 сентября 2026 |
| Runtime | Ollama, RTX 4090, модель целиком в GPU |

Сверить свою копию:

```bash
curl -s "http://<OLLAMA_HOST>:11434/api/tags" \
  | python3 -c "import json,sys;[print(m['digest'], m['details']['quantization_level']) for m in json.load(sys.stdin)['models'] if m['name']=='qwen3:30b-a3b']"
```

Если `digest` отличается от указанного — это другая сборка, и числа полноты
из материалов проекта к ней не относятся.

## Подключение

Адрес модели задаётся переменной окружения `OLLAMA_URL` (полный URL до
`/api/chat`) либо ключом `base_url` в `--model-config` ядра. В репозиторий
адрес не коммитится. Модель доступна через WireGuard-туннель; VPN-профиль —
локальный секрет, его нельзя добавлять в Git, документацию, логи и артефакты
запуска.

| Параметр | Значение |
|---|---|
| Base URL | `http://<OLLAMA_HOST>:11434` |
| Эндпоинт ядра | `/api/chat` |
| Переменные окружения | `OLLAMA_URL`, `OLLAMA_MODEL` |

Проверка доступности:

```bash
curl -s "http://<OLLAMA_HOST>:11434/api/tags"
```

Ожидаемый результат — JSON со списком моделей, содержащим `qwen3:30b-a3b`.

## Параметры запроса

Ядро формирует тело запроса в `run_review.ask_model`. Значения ниже — из кода,
менять их в одностороннем порядке нельзя: на них сняты все замеры.

| Параметр | Значение | Зачем именно так |
|---|---|---|
| `options.num_ctx` | `32768` | документы длинные; 4096 не хватает на фрагмент с контекстом |
| `options.temperature` | `0` | без этого повторные прогоны не сравнимы между собой |
| `options.num_predict` | `4096` | потолок ответа |
| `think` | `false` | иначе Qwen3 подмешивает рассуждение и ломает JSON |
| `format` | JSON Schema | структурированный вывод; ответ вне схемы отбрасывается |
| `stream` | `false` | ответ разбирается целиком |
| `keep_alive` | `"2h"` | модель не выгружается между фрагментами одного прогона |
| таймаут HTTP | `900` с | через туннель документ считается 65–80 с, запас на очередь |

```json
{
  "model": "qwen3:30b-a3b",
  "messages": [{ "role": "user", "content": "…" }],
  "stream": false,
  "think": false,
  "format": { "…": "JSON Schema ответа" },
  "options": { "num_ctx": 32768, "temperature": 0, "num_predict": 4096 },
  "keep_alive": "2h"
}
```

## Что известно про скорость

| Где | Время на документ |
|---|---|
| Локально, тот же хост, что и GPU | ≈ 40 с |
| Через WireGuard-туннель с боевого сервера | 65–80 с |

Разница — сеть, а не модель: одиночный запрос к `/api/tags` идёт 1 с локально
и 8 с через туннель. Таймаут анализа на сервере поднят до 600 с.
