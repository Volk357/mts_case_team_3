# Smoke-проверка реального Analysis Core CLI

Профиль `real-core-cli-smoke-1.0` запускает установленную команду `docreview`
отдельным процессом. Это не импорт функций ядра и не вызов mock-адаптера.

## Сценарии

| Вход | Ожидаемый результат | Exit code | stdout | stderr |
|---|---|---:|---|---|
| Сгенерированный DOCX с русским текстом | `completed`, JSON Schema 1.0, диагностический artifact | `0` | UTF-8 progress log | пусто |
| Минимальный PDF | `failed / UNSUPPORTED_DOCUMENT` | `3` | пусто | пусто |

PDF-сценарий фиксирует текущее честное ограничение ядра: бинарный PDF напрямую не
разбирается. До появления PDF-парсера приложение должно извлечь текст до вызова
ядра. Успешный smoke выполняется на DOCX, который ядро разбирает самостоятельно.

Модель в DOCX-сценарии заменяется локальным HTTP-стабом, возвращающим пустой массив.
Так smoke проверяет настоящий CLI, DOCX-парсер, формальный слой, Review Pack,
формирование результата и артефактов без зависимости от VPN и доступности GPU.
Параметр `think: false` дополнительно проверяется стабом на каждом запросе.

## Запуск

После `npm run setup`:

```powershell
apps/api/.venv/Scripts/python.exe -m unittest tests.test_real_core_smoke -v
```

На Linux используется `apps/api/.venv/bin/python`. Smoke также входит в общую
команду `npm run check`.

Эталонные данные находятся в `tests/fixtures/real-core-smoke/`:

- `manifest.json` — состав профиля и ожидаемые exit codes/потоки;
- `docx-result.json` — стабильная диагностическая проекция успешного результата;
- `docx-analysis-debug.json` — полный ожидаемый debug artifact;
- `pdf-result.json` — полный ожидаемый контрактный отказ.

Динамическое время выполнения и SHA-256 генерируемого DOCX сознательно не входят
в snapshot. Их присутствие и корректность покрываются JSON Schema; сравнивать их
побайтно между машинами нельзя.
