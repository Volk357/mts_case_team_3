# Демонстрационный переход между профилями

Два последовательных запуска показывают подключение другого типа документа без
изменений приложения и Analysis Core. На стартовом экране маршрут проверки
визуально меняет только Review Pack между документом и единым ядром.

## Подготовка

1. Запустить окружение по `docs/docker-compose-runbook.md`.
2. Повторно выполнить `seed-demo`, чтобы каталог зарегистрировал оба Review Pack.
3. Открыть стартовый экран и убедиться, что доступны два профиля.

## Переход 1 Профиль потоковых данных

1. Выбрать «Потоковые данные и витрины» версии `0.2`.
2. Показать маршрут: документ → выбранный профиль → единое ядро анализа.
3. Загрузить `data/synth/synth_1.txt` и запустить проверку.
4. На экране результата обратить внимание на категории, специфичные для
   потоков и витрин, и сохранить запуск в истории.

## Переход 2 Универсальная техническая спецификация

1. Вернуться на стартовый экран.
2. Выбрать «Универсальная техническая спецификация» версии `1.0`.
3. Показать, что в маршруте изменился Review Pack, а последний блок по-прежнему
   называется «Единое ядро анализа».
4. Загрузить `examples/platform-showcase/generic-notification-service.docx`.
5. После проверки показать категории generic-профиля, например
   `AMBIGUOUS_REQUIREMENT`, `INCOMPLETE_API_CONTRACT`,
   `SECURITY_REQUIREMENT_GAP` и `ACCEPTANCE_CRITERIA_MISSING`.
6. Открыть историю и показать две независимые проверки с разными документами и
   сохраненными версиями Review Pack.

Пример намеренно содержит несколько дефектов: субъективную характеристику
скорости, незаполненный таймаут, неполный API-контракт, неопределенную
авторизацию и непроверяемый критерий приемки.

## Вывод для защиты

Открыть страницу `/architecture` и показать единую платформенную схему. Шесть
компонентов текущего MVP отмечены как реализованные, а следующие шаги вынесены
в отдельный блок roadmap.

Приложение, очередь, Analysis Core, модель и экран результатов в обоих переходах
одинаковы. Меняются только документ и версионируемый пакет знаний организации:
manifest, шаблон, таксономия и глоссарий. Подключение нового профиля не требует
форка или новой сборки приложения.
