# 00. Интеграционный контракт

**Статус выполнения:** технические артефакты готовы 3 сентября 2026 года; требуется подтверждение контракта Михаилом и Никитой перед заморозкой версии 1.0.

## Цель

Сделать разработку Михаила и Никиты независимой через один версионируемый CLI/JSON-интерфейс.

## Зависимости

- согласованное разделение ответственности;
- черновой пример замечания;
- понимание способов запуска модели.

## Последовательность работ

### NIK-00-01. Зафиксировать команды CLI

- подтвердить имя executable `docreview`;
- зафиксировать команды `analyze`, `parse`, `validate-pack`, `version`;
- определить обязательные и опциональные аргументы;
- исключить передачу секретов через command line;
- определить поддержку абсолютных и относительных путей.

### NIK-00-02. Зафиксировать результат

- согласовать `ReviewResult`;
- согласовать `Finding` и `Location`;
- сделать `schema_version` обязательным;
- определить обязательность `page`, `block_id` и координат;
- определить формат успешного и ошибочного результата;
- зафиксировать максимум 20 пользовательских замечаний.

### NIK-00-03. Создать машинные схемы

- перенести контракт в JSON Schema;
- добавить позитивные и негативные fixtures;
- проверить кириллицу и nullable-поля;
- предусмотреть генерацию TypeScript-типов;
- добавить контрактные тесты backend.

### NIK-00-04. Согласовать ошибки

- зафиксировать exit codes;
- сопоставить exit code и `error.code`;
- определить retriable и non-retriable ошибки;
- определить timeout и отмену;
- зафиксировать правило: приложение не парсит текст `stderr` для бизнес-решений.

### NIK-00-05. Согласовать версии

- описать совместимые изменения `1.x`;
- определить breaking changes;
- определить реакцию приложения на неизвестную major-версию;
- записывать версии core, Review Pack, модели и промптов.

## Артефакты

- `INTEGRATION_CONTRACT.md`;
- `contracts/review-result.schema.json`;
- `contracts/examples/success.json`;
- `contracts/examples/failure.json`;
- таблица exit codes;
- короткий changelog контракта.

## Проверки

- success fixture проходит JSON Schema;
- каждый негативный fixture отклоняется по ожидаемой причине;
- TypeScript-типы создаются без ручных исправлений;
- строка с кириллицей проходит CLI → файл → backend → frontend без потерь;
- mock и реальное ядро возвращают одинаковую major-схему.

## Критерий завершения

Михаил и Никита подтверждают контракт, а backend-тест принимает валидный fixture и отклоняет невалидный без запуска модели.
