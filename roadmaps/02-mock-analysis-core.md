# 02. Mock Analysis Core

## Цель

Разблокировать разработку приложения до готовности настоящего анализа и гарантировать совместимость с CLI-контрактом.

## Зависимости

- зафиксированные CLI-аргументы;
- JSON Schema `ReviewResult`;
- примеры замечаний от Михаила.

## Последовательность работ

### NIK-02-01. CLI entrypoint

**Статус:** выполнено 3 сентября 2026 года.

- создать executable с командами `analyze` и `version`;
- принять те же аргументы, что реальное ядро;
- писать JSON в UTF-8;
- писать логи только в `stderr`;
- атомарно создавать `--output`.

### NIK-02-02. Success fixtures

**Статус:** выполнено 3 сентября 2026 года.

- сценарий с 10–15 замечаниями;
- сценарий с пустым результатом;
- сценарий ровно с 20 замечаниями;
- разные severity;
- расположения в параграфах и таблицах;
- русские цитаты и длинные section paths.

### NIK-02-03. Failure fixtures

**Статус:** выполнено 3 сентября 2026 года.

- ошибка парсинга;
- неизвестный Review Pack;
- модель недоступна;
- невалидный JSON;
- несовместимая `schema_version`;
- timeout;
- аварийный exit code;
- результат отсутствует после exit code 0.

### NIK-02-04. Управление сценарием

**Статус:** выполнено 3 сентября 2026 года.

- выбирать сценарий через безопасную test/demo-конфигурацию;
- не добавлять специальные ветки mock в production backend;
- обеспечить предсказуемую задержку для проверки progress UI.

### NIK-02-05. Контрактные тесты

**Статус:** выполнено 3 сентября 2026 года.

- проверить stdout/stderr;
- проверить каждый exit code;
- проверить JSON Schema;
- проверить запись через `--output`;
- проверить идентичность `run_id` на входе и выходе.

## Артефакты

- `apps/mock-analysis-core`;
- набор success/failure fixtures;
- контрактные CLI-тесты;
- команда переключения mock/real executable через конфигурацию.

## Проверки

- backend вызывает mock без знания выбранного сценария;
- frontend проходит все состояния через backend;
- mock не создаёт больше 20 замечаний;
- замена пути executable достаточна для перехода на реальное ядро.

## Критерий завершения

Все функции приложения можно разрабатывать и тестировать без доступа к модели и коду Михаила.
