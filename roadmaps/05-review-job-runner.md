# 05. Review Job Runner

## Цель

Надёжно запускать Analysis Core вне HTTP-запроса, отслеживать состояние и сохранять результат.

## Зависимости

- сохранённый Document;
- mock CLI;
- JSON Schema;
- модель `ReviewJob`;
- доступный Review Pack.

## Последовательность работ

### NIK-05-01. Создание задания

**Статус:** выполнено 3 сентября 2026 года.

- реализовать service создания job;
- проверить документ и Review Pack;
- создать уникальный `run_id`;
- сохранить статус `queued`;
- запретить случайный двойной submit на уровне idempotency key.

### NIK-05-02. Рабочая директория

**Статус:** выполнено 3 сентября 2026 года.

- создать `runs/{run_id}`;
- подготовить `input`, `output`, `artifacts`;
- разрешить пути относительно выделенного storage root;
- гарантировать изоляцию параллельных запусков;
- определить политику очистки.

### NIK-05-03. Process Runner

**Статус:** выполнено 3 сентября 2026 года.

- строить список аргументов без shell-интерполяции;
- запускать CLI отдельным процессом;
- передавать безопасное окружение;
- читать stdout и stderr раздельно;
- ограничить размер логов;
- не выводить секреты;
- сохранять PID и время старта.

### NIK-05-04. Timeout и отмена

**Статус:** выполнено 3 сентября 2026 года.

- настроить общий timeout;
- корректно завершать дочерний процесс;
- переводить job в `timed_out`;
- реализовать запрос отмены;
- не принимать поздний результат отменённого job.

### NIK-05-05. Приём результата

**Статус:** выполнено 3 сентября 2026 года.

- проверить exit code;
- проверить наличие output;
- проверить UTF-8;
- проверить JSON Schema;
- сверить `run_id`;
- проверить допустимую major-версию;
- атомарно сохранить raw result и findings;
- перевести job в `completed`.

### NIK-05-06. Ошибки и повтор

**Статус:** выполнено 3 сентября 2026 года.

- сопоставить exit codes с доменными ошибками;
- сохранить диагностическое сообщение отдельно;
- пометить retriable ошибки;
- не повторять job автоматически без лимита;
- повторный пользовательский запуск оформлять новым `run_id`.

### NIK-05-07. Очередь

**Статус:** выполнено 3 сентября 2026 года.

- сначала реализовать один отдельный worker;
- забирать queued job с блокировкой;
- обеспечить восстановление зависших `running` job;
- после стабилизации заменить транспорт на Celery/Redis без изменения service layer.

## Артефакты

- ReviewJobService;
- ProcessRunner;
- worker;
- state machine;
- mapper ошибок;
- integration tests со всеми mock-сценариями.

## Проверки

- success сохраняется один раз;
- два worker не исполняют один job;
- timeout завершает процесс;
- invalid JSON не становится completed;
- run_id mismatch отклоняется;
- restart worker не теряет queued jobs;
- stderr не попадает в пользовательский ответ целиком.

## Критерий завершения

Задание проходит полный жизненный цикл от `queued` до `completed/failed`, а результат доступен после перезапуска процессов.
