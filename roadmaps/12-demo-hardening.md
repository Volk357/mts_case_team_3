# 12. Стабилизация демонстрации

## Цель

Сделать защиту воспроизводимой и устойчивой к сбоям сети, модели, браузера и окружения.

## Зависимости

- реальный end-to-end сценарий;
- Docker Compose;
- согласованный демонстрационный документ;
- финальный Review Pack и версия модели.

## Последовательность работ

### NIK-12-01. Зафиксировать demo release

- закрепить версии application, core, schema, pack, prompts и model;
- создать release tag/commit;
- запретить несогласованные изменения перед защитой;
- записать параметры успешного запуска.

### NIK-12-02. Основной сценарий

- подготовить документ;
- определить последовательность кликов;
- выбрать 2–3 сильных finding для рассказа;
- уложить демонстрацию в заданное время;
- не открывать технические панели без необходимости.

### NIK-12-03. Резервный сценарий

- сохранить валидный ReviewResult;
- подготовить mock profile;
- сохранить исходный документ;
- переключение на резерв через конфигурацию;
- не выдавать сохранённый результат за live-анализ при прямом вопросе.

### NIK-12-04. Ошибки UI

- понятная модель недоступна;
- timeout;
- parser error;
- retry действия;
- отсутствие бесконечного spinner;
- correlation ID для быстрой диагностики.

### NIK-12-05. Репетиции

- три последовательных live-прогона;
- cold start;
- перезапуск браузера;
- перезапуск worker;
- слабое/отсутствующее внешнее соединение;
- Full HD проектор и ноутбук.

### NIK-12-06. Эксплуатационный чек-лист

- свободное место;
- доступность портов;
- состояние контейнеров;
- доступность model endpoint;
- применённые migrations;
- открытая стартовая страница;
- отключённые уведомления и лишние окна.

### NIK-12-07. Наблюдаемость demo

- job duration;
- текущий stage;
- exit code;
- health API/worker/model;
- короткая команда получения последних логов;
- запрет вывода секретов и текста документа.

## Артефакты

- demo release;
- основной и резервный сценарии;
- сохранённый ReviewResult;
- runbook;
- видео полного сценария;
- чек-лист перед защитой.

## Проверки

- три успешных live-прогона подряд;
- резерв включается предсказуемо;
- reload восстанавливает экран review;
- ошибки не требуют терминала для объяснения пользователю;
- демонстрационный текст читаем на проекторе.

## Критерий завершения

Команда может провести полный сценарий в ограниченное время и продолжить защиту при недоступности внешней модели.
