# 13. Демонстрация платформенности

## Цель

Показать, что продукт не зашит под NET и может использоваться разными командами и компаниями через Review Packs.

## Зависимости

- нейтральная модель приложения;
- минимум два Review Pack;
- минимум два документа разных профилей;
- UI выбора пакета.

## Последовательность работ

### NIK-13-01. Убрать NET-зависимости из приложения

- нейтральные названия `Document`, `Review`, `Finding`;
- отсутствие hardcoded defect IDs;
- отсутствие Kafka/витрина-специфичных текстов в UI;
- display name и описание брать из manifest;
- severity отображать универсально.

### NIK-13-02. Review Pack catalog

- просканировать разрешённый каталог пакетов;
- отдать список через API;
- показать company, document type, version и description;
- запретить произвольный пользовательский путь;
- скрыть невалидные пакеты.

### NIK-13-03. Второй профиль

- подключить generic technical specification pack от Михаила;
- подготовить второй документ;
- убедиться, что приложение не меняется;
- показать разные категории findings теми же компонентами.

### NIK-13-04. Демонстрационный переход

- сначала NET document + NET pack;
- затем другой document + generic pack;
- визуально показать смену профиля;
- объяснить: ядро и приложение те же, меняются знания компании.

### NIK-13-05. Архитектурный экран/слайд

- Company Inputs;
- Review Pack;
- Analysis Core;
- Product Application;
- On-premise Model Gateway;
- Feedback loop;
- обозначить реализованное и roadmap.

## Артефакты

- Review Pack selector;
- catalog API;
- второй профиль и документ;
- нейтральные UI-тексты;
- платформенная схема для защиты.

## Проверки

- два пакета работают без новой сборки приложения;
- неизвестный defect ID отображается безопасно;
- смена пакета сохраняется в ReviewResult/истории;
- данные одной проверки не смешиваются с другой;
- UI не предполагает конкретную структуру ТЗ NET.

## Критерий завершения

На защите можно показать второй профиль и доказать, что подключение новой компании выполняется через пакет знаний, а не форк кода.
