# Границы MVP и пользовательский сценарий

## Основной сценарий

1. Аналитик открывает приложение и загружает финальный PDF или DOCX.
2. Приложение проверяет размер, расширение, сигнатуру файла и безопасно сохраняет его.
3. Аналитик выбирает опубликованный Review Pack для своего типа документа.
4. Backend создаёт idempotent review job и сразу возвращает идентификатор.
5. UI показывает состояние; worker запускает Analysis Core отдельно от HTTP-запроса.
6. Core читает документ и Review Pack, выполняет формальные и LLM-проверки через
   внутренний model gateway, проверяет цитаты и оставляет не более 20 findings.
7. Backend валидирует JSON, сохраняет исходный результат и публичные проекции.
8. Аналитик видит 10–15 приоритетных карточек: место, цитату, возможную проблему и
   предлагаемое уточнение.
9. Аналитик принимает или отклоняет каждое замечание и при необходимости исправляет
   исходный документ самостоятельно.

## В MVP входит

- PDF и DOCX;
- один документ на один review;
- выбор только из разрешённых Review Packs;
- локальная OpenAI-совместимая LLM;
- формальные и LLM-проверки;
- асинхронное выполнение, polling, timeout и понятные ошибки;
- максимум 20 локализованных findings;
- решение аналитика по finding;
- история как минимум в пределах demo-контура;
- два профиля на демонстрации: NET и generic technical specification.

## В MVP не входит

- автоматическое переписывание документа;
- замена обязательного человеческого ревью;
- realtime-подсказки во время набора текста;
- интеграция с Confluence/MCP;
- обучение модели после каждого клика;
- произвольная загрузка пользователем исполняемых rules/prompts;
- OCR сканов низкого качества и все офисные форматы;
- полноценная enterprise-аутентификация и горизонтальное масштабирование.

## Состояния сценария

| Состояние | Что видит пользователь | Текущее состояние реализации |
|---|---|---|
| Upload | Зона загрузки, проверки формата и размера | Реализовано |
| Pack selection | Разрешённые пакеты с названием и версией | Следующий этап |
| Waiting/analysis | Безопасная стадия и polling | Backend реализован, UI предстоит |
| Result ready | Список findings и навигация | API реализован, UI предстоит |
| Failed/timed out | Понятная ошибка и возможность нового запуска | Backend реализован, UI предстоит |
| Feedback | Решение и комментарий аналитика | Модель данных реализована, API/UI предстоят |

## Демонстрационная граница

Минимально убедительная финальная демонстрация: два разных документа проверяются тем
же приложением и ядром, но разными Review Packs. Переключение профиля не требует
изменения или новой сборки кода приложения.
