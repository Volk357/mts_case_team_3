# Допущения, риски и способы проверки

| Допущение или риск | Вероятность / влияние | Что делаем до финала | Сигнал решения |
|---|---|---|---|
| Synthetic defects не отражают реальные причины возврата ТЗ | Высокая / высокая | Внешняя слепая оценка на документах кейсодателя и разбор расхождений | Recall и precision не проседают критически относительно synthetic set |
| При приоритете recall пользователь утонет в придирках | Средняя / высокая | Жёсткий предел 20, целевой диапазон 10–15, ranking и feedback | Полезными признаются ≥60%, время просмотра приемлемо |
| Намеренные пропуски вызовут false positive | Высокая / средняя | Явные exclusions и `not applicable` в Review Pack, чистые контроли | Не более 3 FP на чистом документе |
| LLM выдаст неверную цитату или JSON | Средняя / высокая | Проверка цитаты, schema validation, детерминированный fallback и безопасная ошибка | 100% принятых результатов валидны, location accuracy ≥95% |
| Контекст 4096 токенов недостаточен для больших таблиц | Высокая / высокая | Структурный parsing/chunking и выбор релевантного контекста | Длинный тестовый документ не теряет ключевые типы дефектов |
| Локальный model endpoint недоступен на защите | Средняя / высокая | Connectivity preflight, timeout, сохранённый безопасный demo-result | Основной и резервный demo проходят по чек-листу |
| Analysis Core не совпадёт с CLI/JSON-контрактом приложения | Средняя / высокая | Упаковка зависимостей, adapter и contract tests до UI-интеграции | Один CLI одинаково запускается evaluation runner и worker |
| «Платформа» останется декларацией одного кейса | Средняя / высокая | Второй generic pack и документ другой структуры | Оба профиля работают без изменения приложения |
| Документы или VPN-ключ попадут в публичный Git | Низкая / критическая | Ignore rules, synthetic data, проверка истории и логов | В репозитории нет реальных документов, ключей и цитат из них |
| Двух разработчиков не хватит на полную enterprise-версию | Высокая / средняя | Жёсткая граница MVP; auth/масштабирование оставить roadmap | Стабильный основной сценарий важнее числа функций |

## Ключевые открытые вопросы к кейсодателю

1. Какой минимальный Recall@20 будет считаться убедительным на финальной оценке?
2. Какие типы замечаний являются обязательными независимо от общего лимита?
3. Как формально учитывать дефект отсутствия, у которого нет дословной цитаты?
4. Какие исключения должны быть глобальными, а какие — частью конкретного шаблона?
5. Можно ли получить обезличенный baseline существующего Confluence-решения на том же
   тестовом наборе?
6. Какой feedback аналитика считать истинной меткой: первое решение или результат
   последующего согласования с разработчиком?
